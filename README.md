# PM Team Skill — 多 Agent 产品经理团队（v2.1）

> 把产品迭代拆成 6 个标准阶段，5 个专业 Agent 角色协作，评审攻防挖出真实漏洞，决策全程留痕。

**[🎮 Interactive Playbook：你来当产品总监](https://gnomeshgh0714.github.io/pm-team-skill/playbook/)** · 5 分钟体验真实战例——对评审挖出的 5 项严重问题逐项裁决，看你的判断与真实总监是否一致

---

## 为什么做这个

单个 LLM 做产品方案的问题是**没有观点冲突**——它会和稀泥。这个 Skill 把产品经理团队的协作结构显性化：

- **评审攻防**：评审专员只提问题不给方案，角色对立制造结构化冲突。真实战例中第一轮就挖出 5 项严重问题（状态机死锁、数据模型根本性错误、安全合规漏洞），全部在开发前修复
- **决策留痕**：总监对每条评审意见逐项裁决、写明理由、入日志——判断力可追溯、可复盘
- **能力升级**：L1 走完流程 → L2 发现问题 → L3 沉淀技能 → L4 适应新方向

## 真实战例（Playbook 素材来源）

学术论文审稿协作平台第一轮迭代，**单日完成 6 阶段闭环**：

| 指标 | 数据 |
|---|---|
| 正式文件 | 14 份 / ~7000 行（用研 272 行、PRD V1.0 1793 行 → V1.1 2175 行、评审 572 行、复审 552 行） |
| 评审产出 | 12 条问题（5 严重 + 7 中等），结论「需重大修改」 |
| 修改落实 | 必须 7/7 + 建议 7/7，复审通过 |
| 决策留痕 | 10 条（含 8 条复盘期新增） |
| 能力验收 | L1 + L2 双通过，沉淀 3 个可复用技能 |

## 6 阶段工作流

```
① 用研输入 → ② 产品设计 → ③ 评审攻防 → ④ 总监终审 → ⑤ 落地执行 → ⑥ 复盘优化
   子Agent      子Agent       子Agent      主Agent      子Agent       主Agent
```

支持**快速模式**（4 阶段）：需求梳理 → PRD → 评审 → 终审，适合中小需求。
